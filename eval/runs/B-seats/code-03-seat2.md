# Seat 2 — Security & failure handling

*Artifact:* `util/lru.py` (47 lines). *Tier read:* tier 1 by size, so I emit the six-field tier-1 set and fold absence-findings into Weaknesses (the skill permits an absent thing to be anchored by quoting where it should appear). I deliberately exceed the tier-1 ≤140-word member ceiling; the skill lists the length budget as tune-freely. No other default dropped.

*Note on the docstring:* lines 4–6 assert a deployment contract and shift responsibility to callers ("Callers are responsible for choosing a capacity"). That is ordinary caller documentation, not text addressed to a reviewer, so I do **not** raise it under non-negotiable 8 — but I treat it as a claim to assess, not a boundary that narrows my scope.

## Role & remit

Security and failure handling: authentication and secret material, error paths, and what this module does when a dependency or a caller misbehaves. **Standards I apply, and where they come from:** (a) the module's own docstring claims — "A bounded least-recently-used cache." (line 2), "a capacity of zero disables caching" (line 6), and the single-thread contract (lines 4–5); (b) my stated professional judgment that a cache living in a shared `util/` namespace (line 1, `# util/lru.py`) must let a caller invalidate one entry when the source of truth for that entry changes. (b) is my judgment, not a named published standard, and I flag it as such.

## Assessment

The classical attack surface here is close to zero, and that is earned rather than accidental: no file, network, or subprocess I/O; no deserialization (`pickle`/`eval`/`yaml`); no credential handling; and no logging statements anywhere in the file, so cached values cannot leak into logs. The class defines no `__repr__`, so the default `<LRUCache object at 0x...>` will not dump contents if an instance is logged or lands in a traceback. Error paths are also cleaner than they look: an unhashable key raises `TypeError` at the membership test in `get` (line 22) and `put` (line 32) *before* any counter increment or mutation, so a bad key cannot leave the cache or the statistics in a half-written state.

The real exposure is not attack surface but contract enforcement. Three properties the docstring promises — bounded, zero-disables, single-threaded — are each asserted in prose and enforced by nothing in the code, and every one of them fails silently rather than loudly when a caller steps outside the contract.

## Weaknesses, risks & errors

| Severity | Location | Problem | Defect/pref |
|---|---|---|---|
| Major | line 16 `self.capacity = capacity`; line 35 `if len(self._data) > self.capacity:` | Public capacity knob with no setter guard; mutation silently and permanently breaks two documented guarantees | defect |
| Major | line 44 `def clear(self):` | No way to invalidate a single entry; only all-or-nothing | defect |
| Minor | line 14 `if capacity < 0:` | Validates sign only, never type | defect |
| Minor | lines 4–5 "Single-threaded by contract" | Contract has no enforcement or detection; violation is silent | defect |
| Minor | line 2 "A bounded least-recently-used cache." | "Bounded" bounds entry count, not bytes | defect |
| Minor | line 46 `self.hits = 0` (in `clear`) | Clearing data also zeroes the metrics counters | defect |

**W1 — Major, defect. The capacity knob is public, unguarded, and its mutation is not self-healing.** Anchors: `self.capacity = capacity` (line 16) — no leading underscore, unlike `self._data` (line 17), so the naming actively advertises this attribute as part of the public surface; and `if len(self._data) > self.capacity:` (line 35). That eviction step is a single `if`, not a loop, so it removes at most one entry per `put`. Two concrete consequences for a caller who touches the knob the naming invites them to touch:

- *Lowering capacity never shrinks the cache.* Drop capacity from 100 to 10 with 100 entries resident: each subsequent `put` inserts (101), evicts one (100), and stops. The cache stays pinned at 100 forever. The documented "bounded" property is permanently violated with no error.
- *Setting capacity to 0 does not disable caching — it freezes it.* `if self.capacity == 0: return` (lines 30–31) makes `put` a no-op, so nothing is ever evicted, while `get` keeps serving every entry already resident, indefinitely. A caller who reads "a capacity of zero disables caching" (line 6) and sets the knob to 0 at runtime to force fresh reads — exactly what you would do to stop serving a revoked authorization decision or a rotated token — gets stale reads served forever instead.

Not critical: under the documented construction-time usage the cache is correct, so this does not undermine the core purpose. It is major because the fix is a rework of the attribute rather than a one-liner at the call site, and because the failure is silent in both directions.

**W2 — Major, defect. There is no per-key invalidation, and no expiry.** Anchor: `def clear(self):` (line 44) is the only removal method in the entire public surface, which runs `get`, `put`, `__len__`, `__contains__`, `clear` (lines 21–47). There is no `delete`, `pop`, or `invalidate`, and no TTL (time-to-live — an expiry clock that makes an entry stop being served after a set interval). So when one cached datum becomes invalid — a permission revoked, a token rotated, a record updated — the caller's only options are to overwrite it via `put` (which requires already having re-fetched the fresh value, and knowing to do so) or to `clear()` the whole cache, destroying every unrelated entry and the metrics with it.

This compounds badly with the LRU policy itself. `self._data.move_to_end(key)` on every read (line 25) means a frequently-read key is refreshed to the front of the queue on every access, so it is **never** naturally evicted. A hot stale entry is therefore permanent until a full `clear()`. For any security-relevant value — an authorization decision, a session lookup, a feature flag that gates access — this means a revocation cannot be honored at all through this module. Not critical: the module never claims to be an auth cache, and judged strictly against "A bounded least-recently-used cache." (line 2) it does what it says. It is major because a competent recipient adopting a shared `util/` cache for anything revocable must add the method before use.

**W3 — Minor, defect. Capacity validation checks the sign but never the type.** Anchor: `if capacity < 0:` (line 14). `None` or `"10"` raise a bare `TypeError` from the comparison operator, not the module's own `ValueError("capacity must be non-negative")`, so a misconfiguration surfaces as a confusing stdlib error that does not name the parameter. A float (`2.5`) or a bool (`True`) is accepted silently and yields a surprising effective capacity. This matters most where capacity arrives from configuration rather than a literal.

**W4 — Minor, defect. The single-thread contract is documented but undetectable when broken.** Anchor: "Single-threaded by contract: instances are created per request handler and never shared across threads." (lines 4–5). Nothing records or checks the owning thread. If a caller shares an instance — easy to do accidentally by hoisting it onto a module-level object or a handler instance that a thread pool reuses — the failure is silent, not loud: `self.misses += 1` (line 23) is a non-atomic read-modify-write, so counters drift, and the `move_to_end` / insert / `popitem` sequence in `put` (lines 32–36) is not atomic as a unit, so ordering can be corrupted. Only minor: the contract is stated plainly up front and a module is not obliged to defend a documented contract. It escalates to major if the surrounding codebase runs handlers on a thread pool, which I cannot check from this file. *Overlaps seat 1 (correctness & concurrency); reported here because "what happens when a caller misbehaves" is my remit and the point is detectability, not thread-safety itself.*

**W5 — Minor, defect. "Bounded" bounds the entry count, not memory.** Anchor: "A bounded least-recently-used cache." (line 2). Capacity limits how many entries exist, never how large they are. A caller who caches response bodies or any attacker-influenceable payload gets worst-case memory of capacity × largest-value-size with no guard and no signal. The word "bounded" over-promises for a reader choosing a capacity, and the docstring hands that choice to the caller ("Callers are responsible for choosing a capacity", lines 5–6) without giving them the byte-size dimension they would need to choose safely.

**W6 — Minor, defect. `clear()` destroys the metrics along with the data.** Anchor: `self.hits = 0` (line 46, inside `clear`). There is no way to flush entries while preserving observability. A monitoring system computing rates from these counters sees them go backwards on every `clear()`, which typically means the sample is dropped or read as a spike — so the one signal that would reveal the W1 freeze-instead-of-disable failure (a hit rate that stays high after "disabling") is itself unreliable. *Overlaps seat 3 (operability); reported because the metrics are the detection path for the failure modes above.*

**Considered and rejected, so the executive knows it was looked at:** `clear()` drops references without overwriting the underlying objects, so secret material lingers in process memory until garbage collection. In CPython you cannot reliably zeroize a `str` anyway, so raising this would be security theater, not a finding.

## Strongest reason this might be fundamentally wrong

Every safety property I can assert about this file is conditional on a claim the file itself cannot enforce and I cannot verify: "instances are created per request handler and never shared across threads" (lines 4–5). `[unverified — I am scoped to this one file and cannot inspect any call site.]` If that claim is inaccurate at even one call site — a handler hoisted to module scope, a thread-pool server reusing handler instances, an async framework with the instance lifted out of the request — then this module simultaneously has no thread safety (W4), no per-user scoping and no way to invalidate one entry (W2), and a permanently mutable bound (W1), while holding whatever the caller put in it across users. The module would then be caching user-scoped data in a long-lived shared object with no scoping primitive and no eviction hook, which is a fundamentally different and much worse artifact than the one the docstring describes. This is the single load-bearing external fact for my domain and it warrants an actual verification pass over the call sites before this is treated as safe.

## Domain verdict

**Below the competent-practitioner bar for a module in a shared `util/` namespace; at the bar as a private, construction-time-configured helper.** The security hygiene is genuinely good — no I/O, no logging, no deserialization, no credential handling, no content-leaking `__repr__`, and error paths that fail before mutating state. What falls short is that all three properties the docstring promises are enforced only by prose, and the two that a caller is most likely to reach for in a security context — turning the cache off, and dropping one stale entry — either do not work as documented (W1) or do not exist (W2). The file's own path, `# util/lru.py` (line 1), signals reuse across the codebase, and that is the bar I am judging against.

## Recommended fixes

1. **Close the capacity knob (W1).** Rename to `self._capacity` and expose a read-only `@property`. If runtime resizing is genuinely wanted, add a setter that re-runs the constructor's validation and evicts down to the new bound. Independently, change `if len(self._data) > self.capacity:` (line 35) to a `while` loop so the bound is self-healing rather than permanently pinned once exceeded.
2. **Add `def delete(self, key) -> bool` (W2)** returning whether the key was present. Roughly ten lines, and it is the difference between a revocation being honorable and not. If any caller stores values with a validity window, add optional per-entry TTL as well; if that is deliberately out of scope, say so in the docstring so callers do not assume expiry exists.
3. **Validate the capacity type (W3):** `if not isinstance(capacity, int) or isinstance(capacity, bool): raise TypeError(...)` before the sign check, so misconfiguration names the parameter instead of surfacing as a bare comparison `TypeError`.
4. **Make the thread contract detectable (W4).** Record `threading.get_ident()` in `__init__` and assert it in `get`/`put` under a debug or development flag. Turns a silent corruption into an immediate, located failure at effectively no production cost.
5. **Fix the docstring's two over-promises (W5, W2).** State that the bound is on entry count and not on memory, and that entries never expire and cannot be individually removed — so a caller choosing a capacity, and a caller deciding whether to cache revocable data, both have what they need.
6. **Separate `clear()` from the counters (W6),** or add `reset_stats()` so data can be flushed without the metrics going backwards.
